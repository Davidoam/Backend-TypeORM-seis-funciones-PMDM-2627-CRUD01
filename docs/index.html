typeorm-base · Guía de preparación

Antes de clase · Git Bash · Windows

Deja el proyecto listo antes de desconectar Internet

Sigue las pestañas en orden. Usa una terminal Git Bash para cada proceso. El backend y Expo se preparan con Internet; PostgreSQL seguirá funcionando localmente cuando no haya conexión.

Inicia PostgreSQL y comprueba la base

  1. Inicia el servicio PostgreSQL desde Servicios de Windows.
  2. Abre Git Bash y conecta como postgres. En los equipos de clase: contraseña 123456, host localhost, puerto 5432.
  3. Si aún no existe la base, créala una sola vez. Si ya existe, salta el comando de creación.
psql -h localhost -p 5432 -U postgres -d postgres -W
CREATE DATABASE control_databridge;
\q

Comprueba la conexión a la base de práctica:

psql -h localhost -p 5432 -U postgres -d control_databridge -W -c "SELECT current_database();"

La contraseña se establece también en PostgreSQL al instalarlo. Escribirla en .env no cambia la contraseña del servidor.

Clona la misma base común

Comprueba Node.js 22 y clona el repositorio en tu carpeta de usuario:

node --version
git clone https://github.com/albertohdezakkari/typeorm-base.git
cd typeorm-base
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env

Si ya tienes typeorm-base, entra en esa carpeta; no vuelvas a clonarla. Los archivos .env son locales y no se suben a GitHub.

En un móvil, localhost apunta al propio móvil. Para abrir la API desde el móvil, la URL del frontend debe usar la IP local del ordenador y ambos equipos deben estar en la misma LAN.

Instala, compila y arranca NestJS

Haz la instalación con Internet disponible. Conserva el package-lock.json.

cd backend
npm ci --no-audit --no-fund
npm run build
npm run start:dev

Deja esta terminal abierta. Abre una segunda Git Bash desde la raíz de typeorm-base y comprueba la API:

curl http://localhost:3000/salud

La respuesta debe indicar estado: ok y base: control_databridge. Si no conecta, revisa que PostgreSQL esté iniciado y que las credenciales del .env coincidan.

Instala y abre Expo Web

Con Internet disponible, instala las dependencias en la carpeta del frontend:

cd frontend
npm ci --no-audit --no-fund
npm run web

Abre la dirección local que muestra Expo. La pantalla base debe consultar /salud y mostrar la base de datos conectada.

Para comprobar de nuevo desde otra terminal:

curl http://localhost:3000/salud

Comprueba que el equipo ya puede trabajar offline

  1. Antes del corte, confirma que npm ci terminó en backend y frontend, y que ambos proyectos compilan/arrancan.
  2. Con Internet todavía conectado, comprueba que la caché de npm permite reinstalar sin red:
cd backend
npm ci --offline --no-audit --no-fund
cd ../frontend
npm ci --offline --no-audit --no-fund

Cuando terminen las dos instalaciones, corta Internet y vuelve a arrancar PostgreSQL, NestJS y Expo:

# Terminal backend
cd backend
npm run start:dev

# Terminal frontend
cd frontend
npx --no-install expo start --offline --web

Deja Internet desconectado y comprueba que la pantalla responde y curl http://localhost:3000/salud sigue mostrando control_databridge. Solo entonces queda preparada esa máquina.

No ejecutes npm install ni instales paquetes después del corte. Si falla npm ci --offline, esa máquina no está preparada: reconecta Internet, resuelve la instalación y repite el ensayo.
